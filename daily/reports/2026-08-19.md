## 2. 合并结果（7 新条目 + 1 来源补充）

### [新签名]

1. **NUM.05 `gtp_wgrad_dtype_breaks_fp32_reduce_contract`** — Megatron-LM [PR #6624](https://github.com/NVIDIA/Megatron-LM/pull/6624)（修复 PR，open）
   - GTP 关闭 grad-accum fusion 后 wgrad 走朴素 matmul，dtype 跟随计算精度；`--accumulate-allreduce-grads-in-fp32` 下 reduce-scatter 实际在 BF16 里跨 rank 求和、之后才进 FP32 累加器。为何新：不是归约序非确定（NUM.03）也不是 scaler 吞溢出（NUM.04），是 **dtype 契约在一条并行路径上断裂**。
2. **NUM.06 `low_precision_absorption_slingshot`** — [arXiv:2605.06152](https://arxiv.org/abs/2605.06152)
   - 高置信阶段正确类 logit 差超出浮点吸收阈值 → 正确类梯度舍入为 0 → 破坏类间零和 → Numerical Feature Inflation → Slingshot spike。为何新：**部分吸收可以完全无可见 spike 但参数范数仍在疯长**（静默面）；LOSS 现有条目均无此表示精度根因。
3. **PAR.04 `stale_placeholder_wgrad_poisons_main_grad`** — Megatron-LM [PR #6565](https://github.com/NVIDIA/Megatron-LM/pull/6565)（fixes #6078，已 merge 进 closed）
   - GTP placeholder wgrad 是共享 dummy buffer 视图；`zero_out_wgrad`（MTP 共享 embedding）时 DDP hook 执行 `main_grad.add_(param.grad)`，把上一次 backward 的陈旧值加进本 step。为何新：**先静默错、脏够了才 NaN** 的跨 step 状态泄漏，与 PAR.01（单 step 内归约提前开火）不同步。
4. **LOSS.05 `weight_norm_criticality_spike`** — [arXiv:2607.21005](https://arxiv.org/abs/2607.21005)
   - 归一化 scale-invariant 权重 × weight decay → 范数逼近临界边界 → sharpness 骤升 → 突发 spike。为何新：学习率临界性（EoS）之外正交的第二条临界轴，有可检验预测（权重范数轨迹）。
5. **CKPT.07 `dead_or_shadowed_arg_silent_noop`** — ms-swift [#9936](https://github.com/modelscope/ms-swift/issues/9936) + verl [#7460](https://github.com/verl-project/verl/issues/7460)
   - `var:config_default_swallows_cli_override`：参数声明但无 consumer（ms-swift `--mtp_shared_weights`，训出的 MTP 结构与 serving 部署结构错位），或 resolved config 正确但被构造路径硬编码覆盖（verl `critic.model.model_type` → 恒 `value_model`）。
6. **CKPT.08 `epoch_boundary_resume_silent_skip`** — verl [#7401](https://github.com/verl-project/verl/issues/7401)
   - epoch 边界 ckpt resume 静默跳过下一个 epoch，run status 0「正常完成」。为何新：不是加载错权重（CKPT.01–05），是 **resume 契约漏一段数据流**；观测面与 OBS.04 同型但根因独立。
7. **RL-RO.07 `nucleus_truncation_is_bias`** — trl [#6789](https://github.com/huggingface/trl/issues/6789)
   - top_p/top_k/min_p 下 vLLM 返回**截断后重归一化**分布的 logprob，trainer 重算全词表 log-softmax → IS ratio 带逐 token 恒负偏置。为何新：与 RL-RO.01（数值核差）正交的**分布定义不一致**——同权重同 kernel 也存在，温度对称处理的先例修复（#4159）恰好没覆盖截断。
