### 🆕 新签名

- **Megatron #6918 → KER.06 `torch_compile_float_kwarg_stale_constant`** — `clamped_swiglu(_back)` 经 torch.compile 包装后，float 标量 kwargs `clamp_value` 在默认 `specialize_float=False` 下被当编译期常量捕获，之后传新值仍执行按旧值编译的 kernel，前向/AOTAutograd 反向/显式编译 backward 三处静默错值。为何新：KER.03 是「同步/事件序」、KER.04/05 是「环境/框架版本漂移」，这条是**编译栈标量捕获语义**这一独立门控变量；且触发条件真实存在——StepFun Step-3.5-Flash `swiglu_limits`=7 / `swiglu_limits_shared`=16 按专家类型分值、K-EXAONE-2.0-750B 按 layer-indexed 数组，Megatron Bridge 已按层传不同 `activation_func_clamp_value`，第二组层起全用旧值训练。无 crash 无 NaN 无警告。上游 pytorch/pytorch#194976。注意：NVIDIA 维护者初步回复「视为常量不算 bug」，若最终以 wontfix 关闭且无用户侧受影响路径，该条降级待议。

### 🆕 已知类别新实例（补来源）

- **trl #6945 → RL-RO.07 `nucleus_truncation_is_bias`（AsyncGRPO 实例）** — TRL 无条件给所有 vLLM server 强加 `--logprobs-mode processed_logprobs`（理由只适用于有 IS 修正的 trainer），`AsyncGRPOTrainer` 却没有 IS 修正，直接拿 rollout logprob 当 PPO 分母。同策略未动时 ratio=幸存质量 S（top_p=0.7 → coef_1=0.7，落入 clip 外），负优势 token 的 clip 每步误触发。评论区核 vLLM `v1/sample/sampler.py` 证伪「换 raw_logprobs 即修」（raw 在温度/惩罚之前，只换成温度错配）。issue 自身定性为 design question + #6944 已加警告，不占新号。
