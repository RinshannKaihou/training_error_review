## 2. 合并结果（5 新条目 + 4 来源补充）

### [新签名]

1. **PAR.05 `fsdp_degenerate_dp_group_grad_doubling`** — Megatron-LM [#6660](https://github.com/NVIDIA/Megatron-LM/issues/6660)
   - Megatron-FSDP + `optim_grads_params` 下，DP 组退化为单 rank（EP=DP 或 DP=1）时每-microbatch reduce 把「累加」变成「乘 2 再累加」：`buf_N ≈ 2^N·g`（逐 microbatch 实测 absmax 严格 ×2.0）。为何新：不是 hook 计数（PAR.01）不是 dtype 契约（NUM.05），是**退化组 × 每-microbatch 归约**的算术级指数放大；方向不变、幅值假，双重静默（小 N 被 clip 洗掉、大 N 范数溢出反而零梯度空转）。
2. **CKPT.09 `mxfp8_roundtrip_requant_scale_drop`** — Megatron-LM [PR #6666](https://github.com/NVIDIA/Megatron-LM/pull/6666)
   - `--fp8-param-gather` 的 ckpt 只存 BF16 权重不存 MXFP8 block scale，load 侧重量化且 `MXFP8→BF16→MXFP8` 非幂等：dequant max ≤ 224·s 时 scale 掉一档、全 block code 翻倍。为何新：**值与 GEMM 完全无损（bit 级 0 差异）的「编码损坏」**——训练静默继续，但 ckpt parity 检查与 master↔量化派生关系断裂；既有 CKPT 条目均无「检查被骗过但训练无损」这一面。
3. **OPT.04 `global_clip_rescales_corrupted_grad_norm`**（`var:grad_clip_absorbs_sdc_spike`）— Megatron-LM [#6660](https://github.com/NVIDIA/Megatron-LM/issues/6660)
   - 全局 clip 只看 L2 范数：持续性幅值损坏（如 PAR.05 的 2^N）被统一 `clip_coef` **常态化重缩放**放行，`skipped iterations=0`；范数溢出时反向清零全部梯度。为何新：OPT.02 是单步尖峰被吃，本条是持续损坏被洗 + fp32 溢出隔开的放行/清零双 regime；「grad_norm 图正常」的假阴性面首次有实测出处。
4. **SFT.05 `left_pad_scoring_uses_arange_positions`** — trl [#6800](https://github.com/huggingface/trl/issues/6800)
   - 左 pad batch 打分不传 `position_ids`，模型 fallback `arange` → padded 行位置平移；且 `generate()` 用 mask 推位置——**采样与打分在两套位置上分歧**。为何新：不是数值核差（RL-RO.01）不是分布定义（RL-RO.07），是**位置索引输入错**；RoPE 下 no-op（潜伏原因），绝对/学习式位置下整 batch 错（gpt2 实测序列 logprob 差 -34）。
5. **RL-KL.04 `stale_loss_copy_silently_drops_config`**（`var:config_default_swallows_cli_override`）— trl [#6807](https://github.com/huggingface/trl/issues/6807) + [#6808](https://github.com/huggingface/trl/issues/6808)
   - 变体 trainer 复制粘贴的 `_compute_loss` 与主实现漂移：KL 偏置校正、OPSM、entropy bonus、MoE aux loss 在副本里静默缺失；GMPO 开 `use_liger_kernel` 甚至整条被基类路由绕过、训成普通 GRPO。为何新：CKPT.06/07 的「配置无效」发生在**损失计算路径**——错误每步进梯度；MoE aux 缺失沿 MOE.01 放大。
